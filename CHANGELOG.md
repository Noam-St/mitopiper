# Changelog

## 2.0.0 (unreleased)

The single `maker.py` script was refactored into the installable `mitopiper` package.

### Added
- `mitopiper presets reset NAME ...` restores bundled presets to the version of the installed mitopiper (workspaces keep their own copies, so upgrades did not reach them); the old copy is kept as `NAME_old_DATE`.
- Steps can be marked `"temporary": true`: their outputs are deleted at the end of a successful sample job. The mt presets mark their intermediate SAM/BAM files, which took 93 GB of the 116 GB of one preset's full run (10 RNA-seq samples) on the BGU cluster.
- `benchmark/sge_usage.sh`: run time, CPU time and peak memory of every job of an experiment from Grid Engine's `qacct` (failed attempts included), with core-hours per experiment.
- `mitopiper presets set PRESET[,PRESET...] KEY=VALUE ...` changes general settings (`qsub_queue=bioinfo.q`) and step fields (`numt-parser.memory=32G`) without editing JSON. Every name is checked first, so a typo changes nothing.
- mtDNA circularity, based on the original `circulize.py` / `combine_processed_pileups.py`: samples are also aligned to a rotated copy of the mtDNA (`mt_rotation`, default half the mtDNA length), and `mitopiper mt combine-pileups` merges both pileups so the `mt_junction_window` positions (default 400) on either side of the origin come from the rotated alignment.
- NUMT-aware alignment: `mt-variants-numt` aligns to nuclear genome + mtDNA (`mitopiper mt combine-references` drops duplicate mitochondrial sequences of the assembly), keeps reads mapping to the mtDNA with MAPQ ≥ `numt_min_mapq`, and realigns only those to the rotated mtDNA.
- Tutorial (`docs/tutorial.md`): `tutorial/simulate.py` makes a deterministic mtDNA dataset with a known answer: heteroplasmies of 5–20% (one next to the origin), a homoplasmic variant, a diverged NUMT plus a `chrM` copy in a synthetic nuclear genome, NUMT contamination, and reads spanning the origin. The tutorial runs it through all three mt presets and checks the result against the truth. It was run end to end with the tools of `envs/mitopiper-tools.yml`, whose pins resolve.
- Benchmark (`benchmark/`): `run_presets.sh` builds and submits the same samples with every mt preset, and `compare.py` reports depth next to the origin (linear vs circular), reads removed as NUMTs, concordance of calls between presets, and, with a truth table, precision, recall and frequency error. Figures are drawn when matplotlib is installed.
- CI runs the tutorial on a real Grid Engine (`.github/workflows/sge.yml`): it builds daimh/sge, sets up a one-host cluster (`.github/sge/setup_sge.sh`), smoke-tests qsub/`-hold_jid`/arrays/qacct and submits the three mt presets with `-s sge`, checked against the simulated truth. Ubuntu's gridengine packages crash on start-up, hence the source build.
- Reference jobs of builds that run at the same time (e.g. the three mt presets submitted together) no longer corrupt each other's indices: each organism is prepared under `flock` (`references/derived/<organism>/.prepare.lock`), so one job builds and the others wait and then skip what exists. Found on a real Grid Engine, where two `bwa index` on the same rotated reference crashed a job.
- SGE: the monitor asks `qacct` why a job that disappeared from `qstat` ended (once per job; it reads the whole accounting file). It recognises time limits (`failed 37` with the requested `h_rt` used up), memory limits (`h_vmem`), `qdel` and ordinary failures, so killed jobs get the right diagnosis and `--auto-fix`. Found by running the tutorial on a real Grid Engine (daimh/sge 8.1.9).
- Diagnosis: bwa's info line `[M::bwa_idx_load_from_disk] …`, printed by every successful run, no longer counts as a missing index. Only qstat's error states (`Eqw`) are reported as SGE error states.
- SGE: `master.sh` no longer uses `qsub -terse`, which older Grid Engines reject. It reads the job id from qsub's usual answer ("Your job 123 ... has been submitted", also for job arrays), and stops with qsub's message if there is no id. A metadata path that does not exist is reported with the full path that was tried.
- `mitopiper-latest.tar.gz`: after every commit to `master` that passes CI, a CI job packages the commit (`git archive`) and publishes it with its MD5 on the `latest` release. That gives a fixed download link for clusters where `git clone` is not possible.
- CI runs the whole tutorial with the real tools on every push. The job installs `envs/mitopiper-tools.yml` with micromamba and Numt Parser at a pinned commit. It runs `tutorial/run_tutorial.sh`, and `tutorial/check_results.py` then fails the build if the true heteroplasmies, the NUMT filtering, the origin depth or the NUMT search differ from the simulated truth. The results are kept as a build artifact. The unit-test job also runs pyflakes.
- `docs/HPC_TESTING.md`: a checklist for testing mitopiper on a new cluster.
- The reference job builds the indices that a reference you added lacks (when its FASTA is on the build machine), instead of every sample job failing at alignment.
- The monitor no longer counts cutadapt's report lines (`max.err`, "trimming error rate") as errors.
- Per-position tables and heteroplasmy. `mitopiper mt annotate` is a dependency-free port of `process_pileup.py`. It reports coverage per strand, read starts/ends, z-scores, RPM and genes from GFF3/GTF/GenBank, with fixed read start/end counting and gene intervals. It adds allele counts and minor allele frequencies, with depth, frequency and both-strand filters for heteroplasmy calls. `mitopiper mt heteroplasmy` collects the sites of all samples into a sites table and a sample × position frequency matrix. Both run at the end of every mt preset.
- A step setting whose placeholder is empty for a reference (e.g. `--annotation _gtf` without a GTF) is left out instead of rendered without a value.
- Numt Parser (de Flamingh et al. 2023) for NUMT removal: the `mt-variants-numtparser` preset aligns to the mtDNA and to a NUMT reference, classifies reads with `numt_parser.py`, and keeps the reads classified as mtDNA (`mitopiper mt numt-reads`, `samtools view -N`). The NUMT reference is given with `refs add --numt-fasta`, or found in the nuclear genome by the reference job (`mitopiper mt fragments` + `bwa mem -a` + `mitopiper mt numt-regions` + `samtools faidx`). The tool check explains how to install Numt Parser.
- Curated presets in every workspace: `mt-variants`, `mt-variants-numt`, `mt-variants-numtparser` and `rnaseq-expression` (STAR + featureCounts). The mt pileups report every position without a depth cap (`-a -d 0`).
- Derived references (rotated, nuclear + mtDNA) are built and indexed once by the reference job under `references/derived/`. Index detection looks at a step's command, not its name. Structure tokens can be escaped with `\word`.
- Reproducibility: the tool-check job records the path and version of every tool in `output/<exp>/tool_versions.tsv`. Steps can run in their own `container` (Apptainer/Singularity, general setting `container_runtime`) or `conda_env`. `envs/mitopiper-tools.yml` pins the tools of the bundled workflows, and failures to start a container or conda environment are diagnosed.
- `download_mode`: downloads can run on the login node (`login`, by `master.sh` before submitting) or in one download job (`queue`, optionally on `download_queue`), as a stage of their own that samples wait for. Reruns re-download what is missing.
- Array jobs: with `max_running` (a concurrency limit) or `array_jobs`, the sample jobs of an experiment are submitted as one array job (SLURM `--array=1-N%M`, SGE `-t`/`-tc`, LSF `name[1-N]%M`). Monitoring, diagnosis and reruns stay per sample, and SLURM array tasks are queried individually.
- Per-step resources: optional `threads`, `memory` and `walltime` fields on a step. A job asks for the largest threads and memory and the summed time of its steps, never less than the general settings. `_threads` gives a step its own thread count, and the STAR step declares 8 threads and 32G.
- Time limits (`walltime`) are also passed to SGE (`-l h_rt`) and LSF (`-W`), not only to SLURM.
- The package and command are named `mitopiper` (development builds were called `pipemaker`; their workspaces and manifests are still read).
- Nuclear genomes from NCBI Genome: `mitopiper refs fetch-genome ORGANISM [--accession GCF_…] [--nuclear-of SET]`, and an interactive option when an organism has no reference. mitopiper finds the reference assembly through the NCBI Datasets API and warns about its size before asking for confirmation. If none is found, it reports an error and (interactively) lets you enter a path instead. The download itself, verified against NCBI's MD5 sums, and the indexing run in the reference job on the cluster.
- Tool check. Every build gets a `check_<exp>.sh` job that runs first and stops the pipeline if a tool the prep, sample or experiment jobs call cannot be found (e.g. cutadapt behind trim_galore). The same check runs locally before launching. Interactive mode offers to let you fix it yourself, to install into the current environment (conda/mamba from bioconda + conda-forge, or pip), or to add a set-up line to every job and regenerate the scripts. `mitopiper build` halts unless `--auto-fix` (install) or `--no-check` is given, and `mitopiper check [--auto-fix]` runs the check on its own. The monitor, diagnosis and rerun understand the check job.
- Interactive mode chains build → launch → monitor → diagnose → rerun. After the scripts are written it offers to launch them, then opens an interactive monitor session (live table plus the commands `j`, `e`, `r`, `o`, `i`, `q`). The rerun options pre-fill the diagnosed fix. On start-up it offers to monitor the last build. Also available as `mitopiper monitor -i`.
- `mitopiper rerun` / `python monitor.py --rerun`: resubmit failed, killed or skipped jobs, resuming at the step that failed. It supports per-rerun resource overrides, `--free-form` setup lines, `--from`/`--from-start`/`--clean`, and `--auto-fix`. Stuck dependants are cancelled, and reruns are logged in the manifests.
- Failure diagnosis: the monitor explains each failed job (out of memory, time limit, missing tool/reference/index/input, corrupt files, download and disk problems, …) and suggests fixes with ready-to-run commands.
- The `local` scheduler honours dependencies. Jobs whose dependency failed are marked `SKIPPED`.
- `mitopiper monitor` / `python monitor.py`: a live view (`--watch`) of submitted jobs with state, current step, elapsed time and error lines from each job's stderr. `--errors` and `--job` show the failed step and its errors, `--json` gives machine readable output. It detects jobs killed by the scheduler (time/memory limits) through `sacct`/`qstat`/`bjobs`. Job scripts now report their progress to `status/<job>.status`, and `master.sh` records job ids in `jobs.tsv`.
- A step can produce several output files. `output_ext` accepts named outputs (`{"bam": ..., "log": ...}` or `bam=.bam;log=.log`), referenced as `output_<step>:<name>`, `output_<step>:all`, or `outputs_<step>:<name>` in experiment-level steps. The default STAR step exposes its BAM, log and splice-junction outputs.
- Project/study/sample accessions (e.g. `PRJEB12345`, `PRJNA67890`, `SRP012345`) can be given instead of a metadata file. The run table is fetched from the ENA Portal API (`build`, the interactive prompt, and `fetch-metadata`).
- `mitopiper` command with the sub-commands `build`, `presets`, `refs`, `make-tsv`, `cleanup` and `init`, for scripted, non-interactive builds. The interactive menus are still the default.
- SRA metadata support (`SraRunInfo.csv`, SRA Run Selector tables). FASTQ URLs are derived from ENA's mirror.
- Rows without a `fastq_ftp` link are skipped with a warning instead of breaking the build.
- Paired runs listed with an extra unpaired file use only the `_1`/`_2` mates.
- MD5 verification of downloads using ENA's `fastq_md5` column (`verify_md5`).
- Several named references per organism, with switching (`refs use`, `build --reference`).
- NCBI search for the RefSeq mitochondrial genome when an organism is missing from the lookup table. Downloads are validated.
- Experiment-level steps (`"scope": "experiment"`), run after all sample jobs finish, e.g. the new `multiqc` step.
- Job dependencies in `master.sh` for SGE, SLURM and LSF, plus a `local` scheduler for workstations and testing.
- `--dry-run` writes `plan.json` with every resolved variable and command. `--steps`/`--skip` pick steps for a single build.
- Provenance manifest (`mitopiper_manifest.json`) for every build.
- `make-tsv` symlinks local FASTQ files instead of copying and renaming them, and groups Illumina lanes.
- General settings `account`, `walltime`, `parallel_env`, `fail_fast`, `verify_md5`, `download_delay`. `qsub_threads` accepts `auto`.
- Test suite and CI.

### Changed
- **`mt-variants-numtparser` is haplotype-aware.** Numt Parser compared each read with the reference mtDNA, so a read carrying the sample's common allele where the rCRS has a rare one (4769, 8860) was closer to a NUMT carrying that allele and was removed: on a human RNA-seq project two real homoplasmic variants were lost in every sample. Each sample's own mtDNA (`mitopiper mt consensus`: the reference with its major alleles) is now what Numt Parser compares the reads with, and `undetermined` reads are kept by default (`cymt-reads.keep=not-numt`). The tutorial reproduces the case with a recent NUMT on chr3 that carries the samples' allele at 10,000: the old comparison lost that variant (depth 0), the new one keeps it (depth 274, as without filtering); the MAPQ filter loses it too (depth 8).
- Scripts are written to `output/<exp>/scripts/<job name>.sh` (`prep_<exp>.sh`, `s_<sample>_<i>.sh`, `e_<exp>.sh`). The submit script is `master.sh`.
- With the `local` scheduler, a failing job no longer stops the remaining jobs.
- The user's metadata file is copied into the experiment, not moved and rewritten.
- Row selections such as `1-4` are inclusive.
- Jobs stop at the first failing command (`set -eo pipefail`, configurable).
- Indexing of automatically downloaded references runs once in `prepare_refs.sh`, before the sample jobs. Before, it was appended to the first sample's script while other samples could already be running.
- Default preset: `samtools sort` writes `<sample>.sorted.bam`, which `index`/`mpileup` then read. Before, it overwrote its input through a glob.
- Default step paths no longer point to a specific cluster (a lab cluster's absolute tool paths).
- `--account=shtolz` (SLURM) and `-P dreem` (LSF) are no longer hard-coded.
- SLURM/LSF logs are written as per-job files inside `stdout/` and `stderr/`.
- pandas and Biopython are no longer needed.

### Fixed
- Clearer output on the BGU test: Numt Parser's summary line says it counts read mates per label and read pairs kept, and `refs list` labels its nuclear and NUMT columns (`Nuclear FASTA`, `NUMT FASTA`).
- A workspace whose NUMT reference was already found does not search again, so deleting the nuclear + mtDNA copy and its index after a run does not cost a new 1-hour index at the next build.
- While Grid Engine had not yet written a finished job's accounting record, the monitor's summary called it an unrecognised failure; it now says to look again in a minute.
- **Homoplasmic variants (`alt_major`) had no depth threshold**: a single read with an error at a barely covered position was reported as a variant. Variants now need the heteroplasmy calls' minimum depth (50) and more than half of the reads. On the BGU RNA-seq data the Numt Parser preset, which removes the most reads, reported up to 28 such positions per sample against 18-20 for the other presets.
- `tool_versions.tsv` says `unknown` for a tool that prints no version (Numt Parser) instead of leaving the column empty.
- A tool given as an absolute path in a step's `path` that does not exist gets the right advice (correct the step's path with `presets set`, rerun with `-p`) instead of `module load /nonexistent/samtools`.
- `mitopiper monitor -i` stays open when every job is done, so `j` and `e` can still be used; it left at once before.
- `fetch-metadata` sorts the ENA run table by run accession. ENA returns the runs in no fixed order, so `--samples 0-1` named different runs depending on when the table was fetched.
- A download with the full size but a wrong MD5 (seen on the BGU cluster) could not be fixed by the suggested rerun: `wget -c` found the file complete and the checksum failed again. The download step now deletes the file and downloads it once more when the checksum fails, and a checksum failure in the download step is always diagnosed as "resume at `wget`, deleting its output first".
- **The reference jobs' lock did not work across nodes** on the BGU cluster's GPFS (`flock`): two reference jobs indexed whole genomes at the same time. The lock is now a directory (`mkdir` is atomic on network file systems), kept fresh by its owner and taken over when a killed job left it behind for 10 minutes. `flock` is no longer needed.
- The NUMT search aligned the mtDNA fragments to the user's nuclear FASTA, building a 5 GB `bwa` index next to it (in someone else's folder, or failing if read-only), while `mt-variants-numt` indexed the nuclear + mtDNA copy of the same genome. Both now use the nuclear + mtDNA reference in the workspace: one index, nothing written next to the user's files.
- `mt combine-pileups`, `mt annotate` and `benchmark/compare.py` crashed on pileups with bytes that are not UTF-8 (`'utf-8' codec can't decode byte 0x81`, seen on real data in `circular-merge`). Pileups and SAM files are now read byte for byte.
- **Grid Engine reuses job numbers**, so `qacct -j ID` can return other users' jobs from months ago (seen on the BGU cluster): the monitor and `benchmark/sge_usage.sh` now only use records with the job's name, submitted after the job was. Before, `sge_usage.sh` added those jobs' run time and memory to the experiment's totals, and the monitor could take an old record for a job whose own record was not written yet.
- On Grid Engines that record a time limit as `failed 100` with no `category` line (N1GE 6.0), a job killed by its `h_rt` was reported as cancelled, with a plain rerun as the fix. The requested `h_rt` is now read from the job script, and a kill at that limit is a time limit (fix: more time).
- `benchmark/sge_usage.sh` is now a wrapper of `sge_usage.py`: one row per submission, array tasks counted once each.
- **`max_running` broke every Grid Engine build on SGE before 6.2** (no `-tc`; seen on the BGU cluster, N1GE 6.0u8): `master.sh` stopped after the check and reference jobs. When the array job is rejected, `master.sh` now submits the sample jobs one by one, each waiting for the job `max_running` places before it, so the limit still holds.
- Jobs that `master.sh` never submitted because it stopped on an error are shown as such by the monitor ("never submitted", with a diagnosis), and `rerun` submits them. Before, the monitor reported no failures and `rerun` had nothing to do.
- **`refs fetch-mt "Homo sapiens"` downloaded the Denisovan mtDNA** (NC_013993.1, "Homo sp. Altai"): the NCBI search includes related taxa and the first hit was taken. Common model organisms now have their RefSeq mitogenome built in (human: NC_012920.1, the rCRS), the search is restricted to the exact taxon and checks every hit's organism, and the downloaded record's title is printed, with a warning when it names another organism. Found on the BGU cluster.
- Jobs whose Perl tools (FastQC, Trim Galore) load modules of another Perl installation (`Perl API version ... does not match`, `Can't locate ... in @INC`, caused by `PERL5LIB`) get a diagnosis and the fix `unset PERL5LIB PERL5OPT`, instead of an unrecognised failure. Seen on the BGU cluster.
- `rerun --preset` writes the check job for the tools of that preset. It used the tools recorded at build time, so a rerun after fixing a tool path failed the check again. Found on Grid Engine.
- A truncated FASTQ is diagnosed as corrupt input when FastQC is the step that finds it ("Ran out of data in the middle of a fastq entry"), instead of an unrecognised failure. Found by truncating a file on Grid Engine.
- `tool_versions.tsv` no longer records Java's "Picked up JAVA_TOOL_OPTIONS" notice as FastQC's version when that variable is set, and leading spaces of version lines are removed.
- The rotated mtDNA is now shifted by half its length (`mt_rotation` = `half`, was 500 bases). With 500, positions 1–400 lay 100–500 bp from the end of the rotated copy, so paired reads there were lost again and depth in the circular pileup fell by up to half between positions 250 and 400 (`mt-variants`; origin depth 0.87 → 0.93 of the rest in the tutorial). Workspaces created earlier keep `mt_rotation` 500 in `config/<preset>/general_settings.json`: set it to `half`.
- csh/tcsh jobs check every command, including pipelines starting with `echo` such as the MD5 check, so a corrupt download stops the job. With `fail_fast` off they report the exit status of the last command, like bash, instead of always `DONE`.
- `rerun --clean` from the download step works under csh/tcsh: file patterns are removed with `find` instead of an unmatched `rm` glob ("No match").
- Rerun jobs only wait for jobs resubmitted by the same rerun. Reruns of builds made without status files (older versions, csh/sh/dash) no longer skip themselves.
- `monitor --job NAME --errors --watch` keeps watching while the job runs.
- The local scheduler always records the outcome of the current run, even for shells without status tracking.
- Diagnosis: a missing or corrupt file is traced to the step that writes that file, matched by folder *and* extension and never later than the failed step. Before, a `view` failure on a missing `.sam` suggested resuming at `index`, and a corrupt trimmed FASTQ pointed to `fastqc`. A corrupt file that no step of the build produces gets no automatic resume point.
- `rerun --auto-fix` / `monitor --rerun` ignore a suggested resume step that is not before the failed step of that build, instead of aborting the whole rerun.
- csh/tcsh jobs report their status (exit status checked after each command) and honour `fail_fast`. Automatic reference indexing uses csh syntax under csh/tcsh. The `local` scheduler records the exit code of jobs that cannot report it themselves.
- SGE: dependent jobs no longer run after a failed dependency (`-hold_jid` releases them anyway). Every dependent job checks its dependencies and marks itself `SKIPPED`.
- Jobs of untracked shells that have left the scheduler show as `ENDED` rather than `UNKNOWN`, so they are not resubmitted and `--watch` terminates.
- `monitor --errors --watch` no longer stops while jobs are still running.
- The stderr scanner notices a log that was rewritten (e.g. by a local rerun) even if it grew past the previous read position.
- `build --steps <experiment-level step>` builds only that job instead of reporting "No job scripts were generated", and empty per-sample scripts are no longer written.
- Ending input (Ctrl-D or piped answers running out) and piping output into `head` no longer print Python tracebacks.
- Placeholders are resolved by dictionary lookup; `eval()` of user text was removed.
- Downloads use Python's `urllib` with retries; the reference download no longer shells out through `os.system`.
- `command_input_dir_path` pointed to the output directory.
- The thread guess was computed but never used.
- `output_file` settings are resolved before the sample name is appended.
- Structure tokens with commas or brackets (e.g. `-t 1,2`) are kept intact.
- Re-activating a step in the menu appended it to the run order incorrectly.
- `cleanup` no longer deletes every workspace file whose name contains "run".
- SLURM `--output` pointed at a directory.
